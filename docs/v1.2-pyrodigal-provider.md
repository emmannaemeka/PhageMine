# Pyrodigal DNA provider (v1.2 Step 3)

Pyrodigal 3.7.1 is exposed as the native-Python `pyrodigal` gene-model
provider. It is distinct from the external `prodigal` provider and uses the
common `GeneModelProvider` contract.

The documented default is Pyrodigal `GeneFinder(meta=True)` for isolated viral
DNA sequences, with `closed=False`, `mask=False`, `min_gene=90`,
`min_edge_gene=60`, and `max_overlap=60`. Meta mode uses Pyrodigal's
provider-native pre-trained model and translation-table behavior; the effective
table is preserved in the raw record. It does not claim alternative-code
support in this mode. Pyrodigal's minimum-gene policy means small ORFs are not
claimed as supported by default.

Pyrodigal exposes zero-based inclusive `begin`/`end` coordinates. The provider
converts them exactly once to PhageMine's 1-based inclusive coordinates, retains
the raw values, derives strand/frame, and verifies the extracted CDS and
translation. Invalid alphabets and unsupported RNA requests fail explicitly.

Because Pyrodigal is an in-process library, raw provenance is serialized as
`pyrodigal.tsv` plus `pyrodigal.json`; no fictitious raw GFF is generated.
Records include native coordinates, strand, partial flags, start type,
effective translation table, nucleotide sequence, protein sequence, version,
parameters, and input checksum.

`run_observational_comparison()` can execute PHANOTATE and Pyrodigal together
for development diagnostics and writes `comparisons/phanotate_vs_pyrodigal.tsv`.
This does not alter the pipeline's final CDS set: PHANOTATE remains
authoritative in Step 3, and no Pyrodigal-only model enters final annotation.
RNA providers, consensus selection, Prodigal-gv, and benchmark execution are
deferred to later steps.
