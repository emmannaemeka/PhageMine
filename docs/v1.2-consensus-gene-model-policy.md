# v1.2 conservative consensus gene-model policy

PhageMine separates candidate reconciliation, evidence-based adjudication, and
final selection.  The `phanotate-only` policy is the default and preserves the
legacy PHANOTATE CDS set exactly.  `consensus` is an experimental, opt-in policy
(version `1.0`) implemented in `gene_model_selection.py`; its records are
additive and auditable.

Consensus is not a majority vote.  Provider counts and method-family/lineage
counts are descriptive only, since Prodigal and Pyrodigal share ancestry.
Exact coordinate/strand agreement is selected conservatively.  PHANOTATE-only
calls are retained for review, while non-PHANOTATE caller-specific calls are
rescue candidates and are not automatically added.  Split/merge, strand, and
complex conflicts fall back to PHANOTATE when available.  Alternate starts or
stops can replace PHANOTATE only when an existing adjudication recommendation
has comparable, genuinely discriminating evidence and the model is valid.

The shared v1.2 DNA consensus workflow used by `run`, `annotate`, and `batch`
invokes PHANOTATE + Pyrodigal + Prodigal-gv.  The `standard` and `extended`
profile names are retained for reproducible configuration; neither silently
adds command-line Prodigal, which remains a diagnostic/legacy provider.  No
arbitrary weights or probabilities are used (`confidence_calibrated=false`).
Model-specific search
evidence may inform a recommendation, but final downstream annotation must be
run on the selected protein sequence and may reuse cached evidence only when
its complete sequence/database/program fingerprint matches.

The consensus provider set is executed through one shared internal pipeline
implementation for `run`, `annotate`, and each isolated `batch` member.  A
required-provider failure is fatal for that genome and is never relabelled as
PHANOTATE-only success.  This policy remains experimental until independent
validation and blinded biological review are complete.  It does not alter the
frozen v1.1 benchmark.
