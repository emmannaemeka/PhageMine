# v1.2 gene-model provider architecture

Step 2 introduces an algorithm-independent provider contract without changing
biological gene selection. Providers are prediction engines; reconciliation and
model selection remain separate layers.

## Contract

`GeneModelProvider` exposes stable `provider_id` and display `name`,
`version()`, `available()`, `supports_molecule_type()`, `parameters()`,
`capabilities`, `predict()`, and `raw_output_metadata()`. `predict()` returns
`GenePredictionResult`, containing normalized `GeneModel` records plus status,
command, parameters, input checksum, molecule type, segment identifier,
warnings, and caller-specific raw-output references.

`GeneModel` retains the legacy positional constructor while adding raw caller
identity, caller/version, sequence, coordinate-system, checksum, and source
fields. Coordinates remain 1-based inclusive; raw coordinates are never
discarded.

## Capabilities and registry

Capabilities are explicit machine-readable metadata. The registry currently
contains `phanotate` (PHANOTATE, DNA, external executable), `prodigal`
(Prodigal, DNA, external executable, observational only), `pyrodigal`, and
`prodigal_gv` (native Python viral Prodigal models). None advertise RNA
support. `get_gene_model_provider()` and `register_gene_model_provider()`
allow future providers to be added without changing reconciliation logic.

Provider IDs are stable identifiers and are never derived from executable paths.
Each model also carries `method_family` and `method_lineage`; thus Prodigal and
Pyrodigal remain distinct providers but share the Prodigal lineage, while
Prodigal-gv is a related specialized family rather than an independent vote.
Typed provider errors distinguish unavailable executables, unsupported molecule
types, execution failures, unparseable calls, and invalid output.

## Compatibility and provenance

`create_predictor("phanotate")` remains unchanged for legacy callers, and the
existing PHANOTATE parser/invocation remains authoritative. Pipeline manifests
now add a generic `providers` list while retaining legacy manifest keys.
PHANOTATE remains the final CDS source; Pyrodigal-gv is secondary and
observational for every fresh PHANOTATE DNA analysis (the historical
`--reconcile-orfs` flag remains only as a deprecated compatibility option). No consensus selection,
RNA support, new caller, threshold, or coordinate behavior is introduced in
this step.

Raw PHANOTATE and Pyrodigal-gv representations continue to be persisted exactly in
their caller-specific files. Future providers must follow the same policy.
