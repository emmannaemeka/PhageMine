# Segmented RNA performance analysis (Step 9A)

The segmented RNA entry point keeps biological gene calling segment-local. Each
record is passed independently to Pyrodigal-rv, with its own input checksum,
raw call stream, normalized coordinates, and final GeneModels.

Before this refactor, the recursive segment workflow entered the complete
single-genome pipeline for every segment. Consequently Pfam, VOGDB, Swiss-Prot,
PHROGs (MMseqs2 and PyHMMER), fusion, ranking, report generation, and GenBank
packaging were each constructed in every segment directory. This was repeated
work, not a biological requirement, and explains why a full real-database
three-segment smoke run can be long-running. No deadlock was established.

The run-scoped evidence cache now fingerprints adapter implementation and
provenance (database/program/configuration) together with the protein SHA256.
Identical protein sequences encountered in multiple segments may therefore be
searched once and their evidence attributed independently to each segment's
Protein object. Biological genes are never merged. The cache is intentionally
limited to one run and invalidates on a database or parameter change.

`performance_profile.tsv` records stage timings collected from each segment
manifest and an aggregate genome-scope row. Segment-local caller and output
work remains isolated; downstream evidence attribution remains per protein.
Further broad batching/resource-lifetime changes are reserved for the next
performance phase and were not used to alter biological rules in Step 9A.
