# Prodigal-gv provider (v1.2 Step 6)

Prodigal-gv 0.3.2 is exposed as the native-Python `prodigal_gv` provider via
`pyrodigal_gv.ViralGeneFinder`. It is intended for diagnostic use on viral and
jumbo genomes where viral coding models or unusual coding characteristics may
be relevant; it is not part of the default profile in this step.

The provider uses the documented viral-gene-finder meta mode with explicit
edge/overlap/minimum-gene settings inherited from the Pyrodigal adapter. Native
effective translation-table and partial-call metadata are retained. No
alternative genetic code is inferred or propagated into global PhageMine
annotation; any provider-native interpretation remains observational and
review-required for later adjudication.

Prodigal-gv is distinct from `prodigal` and `pyrodigal` as a provider, but its
`method_lineage` is `prodigal`; provider count must therefore not be read as a
count of independent biological evidence. Method-family and lineage counts are
reported separately in reconciliation outputs.

Raw native records are serialized as `prodigal_gv.tsv` and
`prodigal_gv.json` after one-time coordinate normalization to PhageMine's
1-based inclusive convention. No final CDS model is changed in Step 6:
PHANOTATE remains authoritative and Prodigal-gv is observational only.
